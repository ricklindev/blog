我最近重新理解了 AI Agent

做 Elva 之後，我開始覺得 Agent 最困難的地方，可能根本不是 Agent。真正難的是：你到底有沒有先理解那份工作本身。

On this page我原本以為最難的是技術真正的挑戰是定義問題Agent 才是後面的事我現在的結論

過去幾個月，我花了不少時間做 Elva。這是一個我原本很容易用「Agent 究竟是什麼」來描述的產品。

一開始我也很自然地從技術出發：planner、memory、tool calling、multi-agent，以及是不是需要讓 AI 有一台自己的 computer。

真正困難的不是「怎麼做一個 Agent」，而是「這份工作到底是怎麼被完成的」。

1. 我原本以為最難的是技術

當你開始做 Agent，很容易先問這些問題：

  • 模型要記住哪些東西？
  • 工具要怎麼調用？
  • Prompt 要怎麼拆？
  • 是不是要做 multi-agent？

這些都重要，但它們其實不是最前面的問題。如果你連「一個可靠的人類同事會怎麼完成這份工作」都說不清楚，那 autonomy 很可能只是把原本的混亂放大。

技術上能 autonomous，不代表產品上就像一個可靠的同事。

2. 真正的挑戰是「定義問題」

我現在比較傾向先把現實 workflow 畫出來：人怎麼發現事情、怎麼判斷值不值得做、什麼時候要問別人，以及哪些中間結果必須留下來。

Observe
  ↓
Find a useful signal
  ↓
Form an angle
  ↓
Research
  ↓
Draft
  ↓
Human review
  ↓
Ready to publish

這個流程看起來沒有很「Agent」，但它其實比 architecture 更接近產品本身。

3. Agent 才是後面的事

當 workflow 足夠清楚後，agent framework 才開始有意義。因為這時候你知道它為什麼需要 pause、什麼狀態要保留、什麼工具需要被呼叫，以及失敗時怎麼恢復。

Context 也會變得比較具體

與其問「要不要給模型更多 context？」，我現在更常問的是：「在這個決策點，人類同事原本需要知道什麼？」

4. 我現在的結論

我還是很喜歡 Agent 這個方向。但現在如果有人問我要怎麼開始做 AI coworker，我大概不會先跟他談 framework。

我會先問：你想讓它接手的那份工作，現在到底是怎麼做的？

如果這件事情說不清楚，後面的 autonomy 可能只是在把混亂自動化。

Note如果你正在做 Agent，或正在把一個既有 workflow 自動化，這個問題往往比 framework 選型更早出現。
